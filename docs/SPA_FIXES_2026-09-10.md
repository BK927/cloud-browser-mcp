# SPA 보고서 후속 수정 — 2026-09-10

출발점: `dc9bc93`. 운영 설정·인증·프로필·하드 자원 한도는 이 수정에서 변경하지 않습니다.

## 1. 탭 상태와 탐색 근거

- 탭 종료의 `selected_tab_id`와 각 캐시 행의 selected 상태를 함께 반영합니다.
- URL 변경, 문서 식별자 교체, 같은 문서 이동 이벤트를 구분합니다.
- 명시적 reload와 같은 주소의 새 문서 이동을 URL 동일성 때문에 놓치지 않습니다.
- History API/fragment 구분은 Chromium 이벤트에 근거하며 URL 모양만 보고 추측하지 않습니다.
- 출력 스키마 확장 후에도 전체 도구 명세의 100 KB 제한을 유지합니다.
  기본값인 `additionalProperties:true`만 생략하고 허용 의미는 바꾸지 않습니다.

검증: Windows 실제 Chrome의 신규 SPA 4개와 기존 브라우저 completion 12개 통과.
관련 단위·탐색·출력 스키마 테스트 90개 통과. Pi 적용 전이며 실제 사이트 전반의
호환성이나 메모리 개선을 이 결과만으로 주장하지 않습니다.

## 2. 조회·대기

- 의미 역할 질의는 제목 등 비조작 요소도 찾고 이름 필터 뒤에 반환 개수 제한을 적용합니다.
- 저비용 관찰에서 native 검색창/제목 역할과 중첩 label 이름을 처리하고 제한된 AX 보강을 합니다.
- present/absent와 visible/hidden을 구분하고 검사 예산 부족은 partial로 유지합니다.
- 프레임에도 동일 질의를 적용하며, 쿼리 중 불필요한 스크롤 컨테이너 전수 조사를 건너뜁니다.
- 기존 비밀값 보호와 오래된 노드 거부는 유지합니다.

검증: 실제 Chrome에서 SPA·조회·입력·파일·대기·기존 completion·프레임 테스트 32개 통과.

## 3. 일반 UI 승인

- `balanced` 설정 이름은 보존하고 capability를 `balanced-v3`로 표시합니다.
- 기존 팝업 대상에 연결된 메뉴/도움말 버튼과 구조를 확인한 일부 canvas 편집 도구 선택을 자동 허용합니다.
- 버튼 이름/pressed 속성만으로 허용하지 않으며 제출·민감 설정·파일·삭제·일반 Enter는 계속 확인합니다.
- 도구나 문맥이 관찰과 실행 사이 바뀌면 기존 노드 검증으로 실행을 거부합니다.
- 모든 Excalidraw 버전이나 임의 CSR 버튼을 자동 허용한다고 주장하지 않습니다.

검증: 승인 정책 단위 테스트와 실제 Chrome의 승인·SPA 테스트 합계 93개 통과.

## 4. 메모리 측정 준비와 전체 회귀

- 외부 PC용 `work_memory_probe.py`로 단독/두 작업을 구분해 측정합니다.
- 다른 작업/다른 메모리 예산이면 시작하지 않고, 거절을 반복하지 않으며 시험 작업만 정리합니다.
- 기존 read-only PSS sampler에 swap 한도·PSI·그룹 수명 peak도 추가했습니다.
- 토큰 발급/독립 폐기와 Pi 안전한 시간 확인은 배포 담당자가 수행합니다.
- 절차와 미측정 항목은 [WORK_MEMORY_MEASUREMENT.md](WORK_MEMORY_MEASUREMENT.md)를 참조하세요.

로컬 회귀: 일반 472개 통과/Windows에서 POSIX 5개 건너뜀,
실제 Chrome 82개 통과/옵션 4개 건너뜀. 이후 선택 탭 응답과 검색 공백 정규화를
보강한 영향 범위(실제 SPA/승인, 프록시 검증 순서, 출력 schema) 139개도 통과했습니다.
측정 클라이언트의 독립 정리·부분 open·외부 작업 유입 등 모의 시험 8개 통과.
실제 Pi 측정과 운영 적용, 정확한 최종 커밋 CI는 별도 완료 근거가 필요합니다.

배포 담당자의 준비 검토 후 측정 CLI를 현재 MCP SDK의 `httpx2` 전송에 맞추고
실제 `automation_paused` 필드를 검사하도록 보완했습니다. 네트워크/지속 인증 없이
진짜 SDK 초기화·도구 호출·이미지 수신·stdin 경로를 거치는 통합 검증을 포함해
측정 클라이언트 시험은 10개 통과했습니다.

전체 회귀의 추가 실행에서 고정 300ms 뒤 OOPIF가 연결되었다고 가정하는 테스트와
OAuth 탐색 직후 이전 DrissionPage 문서 핸들을 사용하는 테스트가 각각 실패했습니다.
테스트 준비를 실제 자식 검색창/현재 OAuth 문서의 read-only 조건 대기로 바꿨습니다.
입력·제출은 반복하지 않으며 CSP 차단 및 실제 프레임 입력의 성공 조건은 유지합니다.
보강 후 해당 프레임/OAuth 실제 브라우저 및 측정 전송 테스트 23개가 통과했습니다.
